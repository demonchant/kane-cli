RUN PATCHLOOP FROM A LINK

Sign in on the site.
Run tools on your computer.

Google keeps your hosted PatchLoop session and run history private. A small local runner uses the Kane and Codex CLI sign-ins on your computer and never uploads their local authentication stores.

The Render site queues tasks and stores private run records. The local runner performs Kane browser checks and Codex repairs on your computer. Keep the runner open while you want tasks to run.
01 · PATCHLOOP ACCOUNT

Sign in with Google

Google identifies your private PatchLoop session. It does not sign you into Kane or Codex. Run records are scoped to the Google account that created them.

No provider credential form
02 · BROWSER VERIFICATION

Kane CLI

Install Kane on the computer that will run the local helper, sign in using your TestMu account, and make sure your account has available Kane credits.

npm install -g @testmuai/kane-cli
kane-cli login --oauth

CONNECT THE LOCAL RUNNER

Use the hosted PatchLoop page

  1. Install Node.js 20 or newer, Git, and Chrome on your computer.
  2. Clone the public GitHub repository and run npm ci in the checkout.
  3. Open the PatchLoop website and sign in with Google.
  4. Select Connect local runner, then run the one-time pairing command it shows in PowerShell or a terminal.
  5. Leave that terminal open. Your local runner will claim your queued tasks and sync status and evidence to your private website session.
git clone https://github.com/demonchant/kane-cli.git
cd kane-cli
npm ci

The pairing code expires after 10 minutes and works once. After pairing, start the runner on later days with the command shown on the page without the pairing code. Its runner token stays in the ignored .patchloop/remote-worker/ folder on that computer. To revoke the paired runner, run npm run worker -- --url YOUR_PATCHLOOP_URL --disconnect.

Your Kane and Codex sign-ins, target repository, worktrees, and provider usage remain local. PatchLoop sends task text, progress, pattern-redacted CLI evidence, and the reviewable diff to your private Google-owned session so the website can display the run. Avoid putting secrets in task text or code changes.

Running your own full local workbench is also supported: use npm start and open http://127.0.0.1:4173. See the repository README for the local workflow and optional target repository setup.
